## HIGH — Hard Gate

### 1. White text on all three colored buttons fails WCAG AA — 2.80:1 to 3.76:1 (R-25)

| Pairing | Ratio | Needs | Used by |
|---|---|---|---|
| `#ffffff` on `--color-accent` `#f97316` | **2.80:1** | 4.5:1 | Tambah Cepat dari Perpusnas, Cek ISBN, Tambah Waktu, Tambahkan N Buku |
| `#ffffff` on `--color-primary` `#3b82f6` | **3.68:1** | 4.5:1 | Mulai Lacak, Buka Dashboard, Simpan Konfigurasi, page numbers |
| `#ffffff` on `--color-error` `#ef4444` | **3.76:1** | 4.5:1 | Batal buttons on hover, btn-danger hover |

All are 14px/600 — normal text, so 4.5:1 applies. 18.66px+ bold would qualify as large text (3:1); none of these do.

Fix: darken the button fills rather than the text. `--color-accent` at `#c2410c` or darker clears 4.5:1 against white with the label intact. Do not "fix" this by lightening the text.

### 2. The pending badge pulses below AA half the time — 4.28:1 at the trough (R-25, R-19)

`ui.css:471` — `.badge-pending { animation: pulse-amber 2s infinite ease-in-out }` drops opacity to 0.75. At rest the amber on its own tint measures 6.41:1 (pass). At the 0.75 trough it measures **4.28:1** — under 4.5 for 12px text — for roughly a second out of every two, forever, on every pending row.

This is finding 9's motion problem with an accessibility edge: the animation is not decorative, it is actively degrading legibility.

### 3. `--color-primary` as text is 4.44:1 on the card — marginally under AA (R-25)

`#3b82f6` on the composited card background measures **4.44:1** against 4.5:1 required. It is used as a text color for: the Analisis heading icon (`ui.ts:91`), the Edit modal icon (`ui.ts:371`), the footer link (`ui.css:630`), the edit-button icon (`ui.js:559`), and the 11px "No. Resi" chips (`ui.js:766`).

The 11px chips are the real exposure — smallest text in the app, thinnest margin. Needs one step darker or lighter, not a tolerance.

### 4. No Escape key, no focus trap, no dialog semantics on either modal (R-32)

Grep for `keydown` / `Escape` in `src/` returns nothing. `openEditModal` (`ui.js:406`) and `openQuickAddModal` (`ui.js:654`) only set `display` and `opacity`. Consequences:

- Neither modal can be dismissed with Escape — only by clicking Batal.
- Focus is never moved into the modal and never restored on close. `openQuickAddModal` focuses the textarea; `openEditModal` focuses nothing, so a keyboard user who opens it is still on the row button behind the overlay.
- Tab from inside the modal walks straight out into the page behind it.
- No `role="dialog"`, no `aria-modal`, no `aria-labelledby` on either overlay.

Also in the same rule: the tab bar is `<button>` + `.active` class with no `role="tab"`/`aria-selected`; `#advancedSettings` disclosure has no `aria-expanded`; alert banners have no `role="status"`/`aria-live`, so a screen reader never announces a failed login.

### 5. Inputs are stripped of the focus ring and left with a 1px border tint (R-32)

`ui.css:43` sets `:focus-visible { outline: 2px solid var(--color-primary) }`. `ui.css:313` sets `.form-control:focus { outline: none; border-color: var(--color-primary) }`.

Specificity: `.form-control:focus` is 0-2-0, `:focus-visible` is 0-1-0. The later, higher-specificity rule wins. **Every input, select, and textarea in the app loses the focus outline entirely** and gets only a border-color change from `rgba(255,255,255,0.06)` to `#3b82f6`. R-32 forbids removing the outline without a genuinely better replacement indicator.

Fix: drop `outline: none` from `.form-control:focus` and keep the border tint as an addition, not a substitute.

### 6. Loading, empty, and error states are indistinguishable or absent (R-27)

Three separate failures:

- **Loading is indistinguishable from empty.** `loadBooks` (`ui.js:174`) awaits `fetch` with no pending state. Until it resolves, `booksListBody` is empty, so the table renders the empty state. A user on a slow connection sees "Tidak ada buku dalam pelacakan." while data is still in flight.
- **Empty state names no cause and offers no action.** `ui.js:520` renders an inbox icon and one sentence. It is also the *same* string for three different situations: first run, search returned nothing, and status filter matched nothing. R-27 requires cause plus the one action that fills it.
- **Error state is a transient toast only.** `showAlert` auto-dismisses after 5000ms (`ui.js:885`). There is no in-place error in the table. A user who looks away for six seconds sees an empty table and no explanation.

### 7. Placeholders are fictional catalog data, not obvious placeholders (R-23, R-38)

`ui.ts:137,141,146` — `e.g. Laskar Pelangi`, `e.g. Bentang Pustaka`, `e.g. Andrea Hirata`.

These are not neutral examples. *Laskar Pelangi* is a real published novel by Andrea Hirata, published by Bentang Pustaka, so the three placeholders read as one coherent real catalog entry. R-23 sanctions `Your Name` / `email@example.com` / `[REAL DATA]`. Same issue at `ui.ts:163,167,171` (`e.g. my-custom-topic`, `e.g. -100123456789`, `e.g. https://api.myweb.com/hook`) and `ui.ts:411` (`e.g. 978-602-...`).

### 8. Em dash in page text (R-02)

`ui.ts:6` — `<title>ISBN Notify — Dasbor</title>`. The browser tab is user-visible UI text.

`src/index.ts:3,389,401,419` and `src/scheduler.ts:11` also contain em dashes, but those are developer console logs and code comments rather than rendered text, so I have not counted them. Flagging for your call.

### 9. Enter-to-submit is dead in the settings form (R-26, C-2)

`ui.ts:315-319`: the visible "Simpan Konfigurasi" button is `type="button"` and lives **outside** the `<form>`. It works by programmatically clicking `#btnSaveSettings`, a `type="submit"` button with `style="display:none"` that is the form's only submit trigger via its `form=` attribute.

Consequence: pressing Enter in any settings field submits nothing. A keyboard user has to Tab to the visible Save button and activate it. The form looks and behaves as if Enter works, because it does on every other form in this app (`addBookForm`, `editBookForm`, login) — so the inconsistency is invisible until you use it.

### 10. Row cursor promises an interaction that does not exist (R-26, C-2)

`ui.css:449` — `tr:hover td { ...; cursor: pointer; }`. No `<tr>` has a click handler in `ui.js`. The pointer cursor signals "click this row" and delivers nothing; the real actions are the two icon buttons in the last cell.

### 11. `book.isbn` reaches `innerHTML` unescaped (R-26 — unescaped user-controlled data)

`ui.js:537-539`:

```js
const isbnDisplay = book.isbn
  ? `<span class="font-mono" ...>${book.isbn}</span>`
  : '<span class="text-muted">-</span>';
```

Every other interpolated field in `renderBooksTable` goes through `escapeHtml` — title, author, publisher, dateInfo. `isbn` does not. It also originates from the Perpusnas scrape, so it is not data this app controls. `book.id` is likewise interpolated raw into `onclick` and `aria-label` at `ui.js:559,562`.

### 12. No design direction, and not labeled as a draft (R-37)

No `DESIGN.md` anywhere in the repo, no design notes in `README.md`, and nothing in the commit history. Per R-37 this UI was built without direction, so it must either carry the *"draft without direction"* label with dials ENERGY 1 / RHYTHM 1 / MOTION 1, or get a direction. It currently has neither, and the choices it did make (dark theme, blue+orange, glass, gradient wordmark) are the model's defaults rather than decisions.

### 13. Mobile layout: footer escapes the container, table nests a card inside a card (R-03)

- **Footer is outside `.container`.** `ui.ts:328` — the `<footer>` sits after the closing `</div>` of `.container`. Everything else is capped at 1200px and centered; the footer spans the full viewport with its own `border-top`. On mobile it aligns to the window edge while all content above it aligns to the content column.
- **Card-in-card at ≤768px.** `ui.css:643-671` turns every `<tr>` into a rounded, bordered, padded card, while `.table-container` (`ui.css:415`) keeps its own border and radius around all of them. Each row card floats inside a container card.
- **`data-label` noise on mobile.** `td::before` renders `No.` above a row index that carries no meaning once the table is a list, and `Aksi` above the button pair.
- **Stray closing brace, `ui.css:188`.** The `@media (max-width:1024px)` block closes at line 187; line 188 is an unmatched `}`. CSS error recovery keeps parsing so the page renders, but the file is structurally invalid from that point and the next nested block added there will silently misbehave.

Positive: `prefers-reduced-motion` is correctly handled at `ui.css:65-70`, and tap targets meet 44px via `.btn`/`.btn-icon`.

### 14. R-35 unverified — the app was never run (R-35)

Every execution tool in this session (`PowerShell`, `Bash`, the contrast MCP) returned `free is temporarily unavailable`. I did not start the server, did not click a control, and did not read the browser console.

This gate cannot be claimed as PASS on code inspection alone. It needs a real run before delivery.

## MEDIUM — Purpose-Gate

### 15. Glassmorphism is the page's character trait, not an accent (R-10, dose cap 1-2)

`.glass-card` (`ui.css:81`, `blur(16px)`) is applied to **eight** surfaces: header, stats, analysis, register, tracking table, both settings cards, the login card, and — per book — every card in the Quick Add preview (`ui.js:758` sets `class="glass-card"` on each parsed entry). `.login-overlay` adds `blur(24px)` on top for all three overlays.

Every surface sits in the same frosted layer, so nothing is foreground. `backdrop-filter` is also among the most expensive properties to composite, and here it is blurring an almost-opaque two-stop gradient, so it buys almost no visual payoff for the GPU cost.

### 16. Endless pulse on every pending row (R-19)

`ui.css:471` — a 2s infinite opacity loop per badge, each containing a `loader-2` icon with its own `spin` animation (`ui.js:552`). Ten pending rows means ten badges pulsing in and ten icons rotating, continuously, with no user trigger. Motion dial is undeclared; against any dial this is wallpaper. See also finding 2 — this animation has an accessibility cost, not just an aesthetic one.

### 17. Entire icon set is Lucide via unpinned CDN, with the header logo class reused as a generic heading class (R-04)

`ui.ts:10` — `<script src="https://unpkg.com/lucide@latest">`. Every icon in the app is Lucide, so they all share one thin-stroke rounded look. Icons are mostly relevant (`book-open`, `bell`, `clock`, `save`, `trash-2`), so the relevance test passes — the library-uniformity test does not, and no reason is written down.

Two secondary problems: `@latest` is an unpinned CDN dependency that can change the icon set or break rendering with no code change and no way to reproduce; and `class="logo-icon"` is applied to section-heading icons (`ui.ts:91,186,288,336,371`), so header-logo styling is now a generic heading style, which is how a logo class ends up meaning nothing.

### 18. Five chromatic colors, two of which are the same orange (R-29, R-01)

Core palette: `--color-primary` `#3b82f6`, `--color-accent` `#f97316`, `--color-success` `#10b981`, `--color-pending` `#f59e0b`, `--color-error` `#ef4444`. That is five, against a cap of 2-3 core + 1 accent.

More specifically: `#f59e0b` (pending state) and `#f97316` (accent) are near-identical oranges. The accent and a status signal compete for the same hue, so the badge stops reading as "state" and starts reading as "orange thing". The wordmark also carries a blue gradient (`ui.css:121`, `#3b82f6 → #60a5fa`) with no written hierarchy reason.

### 19. Shadow on every card at rest-on-hover, glow in two more places (R-12, R-13)

`.glass-card:hover` (`ui.css:93`) applies `0 10px 30px -10px rgba(0,0,0,0.5)` to every card, so hovering anything lifts everything. `.tab-btn.active` (`ui.css:157`) and `.hour-pill-label.active` (`ui.css:615`) both add blue glow. No elevation reason is written down for any of the three.

### 20. Uppercase wide-tracked micro-labels (R-06)

`.stat-lbl` (`ui.css:235-238`) and the analysis panel label (`ui.ts:115`) both use `text-transform:uppercase; letter-spacing:0.05em` at 0.75rem. On an Indonesian-language UI, uppercase Latin micro-labels also read as a stylistic tic borrowed from English-language dashboards.

`Plus Jakarta Sans` is not on the banned default roster and is a defensible choice, but it is loaded from Google Fonts with no written brand-character reason, and it is the app's only typographic gesture.

### 21. No light/dark toggle and no written reason for the fixed dark theme (R-21)

Dark-only, with no toggle and no stated reason. This is a personal book-tracking dashboard for library staff, not a developer tool, so "dark because it looks technical" is the trend reason the rule specifically rejects. If dark stays, the reason needs writing; if it does not, the toggle is the work.

### 22. Nearly 40 lines of CSS for a component that does not exist (dead code)

`.hour-pill-label` (`ui.css:587-616`, plus the mobile override at 754) is styled in four blocks and referenced nowhere — grep across `src/` hits only `ui.css`. The scheduler actually uses `<input type="time">` rows built by `addScheduleEntry` (`ui.js:47`). Either a feature was replaced and the CSS was left behind, or an hour-pill picker was half-built and abandoned. Worth deciding which, then deleting.

## LOW — Quality Locks

### 23. Raw enum values leak into Indonesian UI (R-20, R-11)

`ui.js:553` renders `${book.status}` directly, so table badges read `PENDING` / `COMPLETED` while the filter dropdown above them reads `Pengajuan` / `Terbit` and the stat tiles read `Pengajuan` / `Terbit`. The Edit modal's status select (`ui.ts:405-406`) has the same mismatch. One vocabulary, two languages, on the same screen.

### 24. Radius is a near-monotone scale (R-11)

Cards `1rem`, containers `0.75rem`, controls `0.5rem`, chips `0.5rem`, ISBN chip `4px`, badges `9999px`. Six values across the app, and the gap between `0.5rem` and `4px` carries no hierarchy meaning. Not the pill-everything failure the rule targets — it is simply a scale nobody chose.

### 25. No written reason for any major decision (R-31)

The keystone rule. No DESIGN.md, no comments, no commit rationale for: the dark theme, the blue+orange palette, glass on every surface, the gradient wordmark, the `1rem`-vs-`0.5rem` radius split, or the uppercase micro-labels. Every one of these is a decision someone would defend, and none of them currently has a sentence attached.

### 26. Generic dark-glass dashboard (R-30)

Slate-blue, glass, `backdrop-filter`, purple-adjacent dark gradient. Swap the logo and the product name and it reads as a default AI-generated SaaS dashboard. The `Plus Jakarta Sans` + orange accent combination is the most common pairing in this genre.
